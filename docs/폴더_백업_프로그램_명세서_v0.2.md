# 폴더 백업 프로그램 명세서

버전: 0.2 · 수정일: 2026-09-12 · 사용자 추가 설명 및 폴더 화면 반영

## 1. 목적과 요구사항

프로그램을 실행하면 미리 설정된 원본 기본 경로와 백업 기본 경로를 불러온다. 사용자가 GUI에서 백업할 항목을 선택하고 원하는 글을 입력하면, 백업 기본 경로의 같은 이름 항목 폴더 안에 `YYMMDD_입력한이름` 폴더를 새로 만들고 해당 원본의 내용물을 복사한다.

사용자가 확정한 조건은 기본 경로 자동 표시, GUI에서 백업 항목 선택, 오늘 날짜와 입력한 글로 백업 폴더 생성, 같은 이름의 항목별 폴더 안에 저장, 하위 폴더 포함, 원본 수정 금지다. 여러 항목을 체크해 한 번에 실행하는 방식과 중복·실패 처리는 이번 명세의 제안 기본값이다.

| 항목 | 명세 |
| --- | --- |
| 실행 환경 | Windows용 실행형 GUI 프로그램 (`.exe`) |
| 날짜와 이름을 붙이는 대상 | 새로 만드는 백업 폴더 |
| 경로 | 실행 시 설정된 기본 경로 자동 표시 |
| 백업 항목 | `1_LEAD`, `2_CORNER`, `3_BODY`, `4_SIDE`, `5_TERR`, `6_SHSD` |
| 선택 방식 | 체크박스로 하나 이상 선택, 전체 선택·전체 해제 제공 |
| 백업 범위 | 선택한 항목 안의 모든 파일과 하위 폴더 |
| 저장 구조 | `<백업기본경로>\<항목명>\YYMMDD_입력한이름\<원본 내용물>` |
| 실행 시점 | 항목 선택과 이름 입력 후 [선택 항목 백업] 버튼을 누를 때 |
| 백업 방식 | 매 실행마다 선택한 항목별로 새로운 폴더에 전체 복사 |
| 내부 파일명 | 원래 이름과 확장자 유지 |
| 보관 형태 | 일반 폴더 |

## 2. 기본 사용 흐름

1. 프로그램을 실행한다.
2. 최초 실행 시 원본·백업 경로를 설정한다. 이후에는 저장한 경로와 여섯 항목의 목록이 자동으로 표시된다.
3. 백업할 항목을 체크한다. 예: `1_LEAD`, `3_BODY`. 실행 직후에는 모두 미선택 상태다.
4. 이름 입력란에 `설정변경전`처럼 원하는 글을 입력한다.
5. 오늘 날짜가 붙은 폴더명과 선택한 항목별 저장 경로 미리보기를 확인한다.
6. [선택 항목 백업]을 누르면 선택한 원본만 확인하고 각 백업 폴더로 복사한다.
7. 항목별 결과와 전체 성공·실패 개수를 확인한다.

### 기본 경로 설정

공개 배포본의 원본·백업 기본 경로는 비어 있다. 최초 실행 시 사용자가 실제 경로를 입력하고 저장하며, 다음 실행부터 저장한 경로를 복원한다. 실제 장비 주소와 공유 폴더 구조는 공개 문서에 포함하지 않는다.

원본 기본 경로는 여섯 항목이 들어 있는 상위 폴더이며, 백업 기본 경로도 같은 이름의 여섯 항목이 들어 있는 상위 폴더다. 경로 설정값이 없거나 잘못되었으면 실행을 차단하고 경로 설정을 안내하며 임의의 경로로 대체하지 않는다.

## 3. 폴더명과 저장 구조

### 3.1 이름 생성 규칙

- 형식: `YYMMDD_사용자지정이름`.
- 예: 2026년 9월 12일에 `레시피백업`을 입력하면 `260912_레시피백업`.
- 따옴표는 실제 폴더명에 포함하지 않는다.
- 날짜는 [선택 항목 백업]을 누른 시점의 PC 현지 날짜를 사용한다. GUI에서 날짜는 자동 표시하고, 사용자는 날짜 뒤의 글만 입력한다.
- 같은 실행에서 선택한 모든 항목에 동일한 날짜와 입력 글을 사용한다.
- 백업 도중 날짜가 바뀌어도 시작할 때 정한 날짜를 유지한다.
- 실행 전 미리보기는 현재 날짜를 반영하며, 시작 시 최종 경로를 확정한다.
- 한글, 영문, 숫자, 공백, 밑줄 등을 입력할 수 있다.
- 입력값의 앞뒤 공백을 제거하고, 빈 이름이나 경로 구분자·허용되지 않는 문자가 들어간 이름은 이유를 표시해 수정하도록 한다.
- Windows에서 폴더를 만들 수 없는 이름이나 경로는 복사 전에 검사한다. 문자를 임의로 바꿔 저장하지 않는다.

### 3.2 중복 처리

해당 항목의 백업 폴더 안에 같은 이름이 있으면 기존 내용에 합치거나 덮어쓰지 않고 다음 사용 가능한 번호를 붙인다. 중복 번호는 항목별로 결정하고 실제 저장 경로를 표시한다.

| 백업 순서 | 생성 폴더명 |
| --- | --- |
| 최초 | `260912_레시피백업` |
| 같은 날짜·이름으로 다시 실행 | `260912_레시피백업_01` |
| 다시 실행 | `260912_레시피백업_02` |

이미 사용 중인 번호는 건너뛴다. 번호 결정 후 실제 폴더 생성 시에도 중복 여부를 확인해 기존 폴더를 사용하지 않도록 한다.

### 3.3 경로 예시

입력 글이 `설정변경전`, 시작일이 2026년 9월 12일인 경우의 항목별 경로는 다음과 같다. `<원본기본경로>`와 `<백업기본경로>`는 확인 후 설정할 전체 경로를 뜻하며 실제 폴더 이름이 아니다.

| GUI 항목 | 원본 폴더 | 새 백업 폴더 |
| --- | --- | --- |
| `1_LEAD` | `<원본기본경로>\1_LEAD` | `<백업기본경로>\1_LEAD\260912_설정변경전` |
| `2_CORNER` | `<원본기본경로>\2_CORNER` | `<백업기본경로>\2_CORNER\260912_설정변경전` |
| `3_BODY` | `<원본기본경로>\3_BODY` | `<백업기본경로>\3_BODY\260912_설정변경전` |
| `4_SIDE` | `<원본기본경로>\4_SIDE` | `<백업기본경로>\4_SIDE\260912_설정변경전` |
| `5_TERR` | `<원본기본경로>\5_TERR` | `<백업기본경로>\5_TERR\260912_설정변경전` |
| `6_SHSD` | `<원본기본경로>\6_SHSD` | `<백업기본경로>\6_SHSD\260912_설정변경전` |

위 폴더들은 해당 항목을 선택했을 때만 생성한다. `1_LEAD`를 선택한 경우 내부 복사는 다음과 같다. 예시 파일명은 설명을 위한 가상 파일명이다.

| 원본 파일·폴더 | 백업 결과 |
| --- | --- |
| `<원본기본경로>\1_LEAD\TOP.json` | `<백업기본경로>\1_LEAD\260912_설정변경전\TOP.json` |
| `<원본기본경로>\1_LEAD\Config\camera.ini` | `<백업기본경로>\1_LEAD\260912_설정변경전\Config\camera.ini` |
| `<원본기본경로>\1_LEAD\EmptyFolder\` | `<백업기본경로>\1_LEAD\260912_설정변경전\EmptyFolder\` |

날짜 폴더 안에 `1_LEAD` 같은 항목 폴더를 한 번 더 넣지 않는다. 백업 기본 경로 바로 아래에 날짜 폴더를 만드는 구조도 사용하지 않는다. 기존 항목 폴더와 과거 백업은 유지하고, 선택한 항목의 백업 부모 폴더가 없을 경우에만 그 부모 폴더를 새로 만든다.

## 4. 화면과 설정

| 화면 요소 | 동작 |
| --- | --- |
| 기본 경로 | 원본·백업 기본 경로 자동 표시, 필요한 경우 [경로 설정]에서 변경 |
| 항목 목록 | 여섯 항목의 체크박스, 원본 존재·접근 상태, 전체 선택·전체 해제 |
| 오늘 날짜 | PC 현지 날짜 자동 표시 |
| 백업 이름 | 날짜 뒤에 붙일 글 입력 |
| 생성 예정 경로 | 선택한 각 항목의 실제 저장 예정 경로 표시 |
| 선택 항목 백업 | 하나 이상 선택하고 이름을 입력한 경우 실행 가능 |
| 진행 상태 | 준비 중, 복사 중, 완료, 일부 실패, 실패, 취소 표시 |
| 진행 정보 | 현재 항목·파일, 전체 파일 수, 처리한 파일 수, 성공·실패 수 표시 |
| 진행률 | 목록 확인 중에는 준비 중 표시, 이후 처리한 파일 수를 기준으로 표시 |
| 취소 | 진행 중인 백업 중단 |
| 결과 폴더 열기 | 항목별로 실제 생성된 백업 폴더 열기 |
| 상세 결과 | 실패·제외 항목의 경로와 원인 확인 |

- 원본·백업 기본 경로 설정을 사용자별로 저장해 다음 실행 시 자동으로 표시한다. 공개 배포본의 최초 경로는 비워 두고 사용자가 설정한다.
- 입력 이름은 마지막 값을 복원할 수 있지만 항목 체크 상태는 실행마다 모두 해제한다.
- 날짜는 이전 설정에서 복원하지 않고 실행 시점에 계산한다.
- 백업 중에는 입력값 변경과 중복 실행을 막고, 화면은 계속 반응해야 한다.
- 프로그램 시작만으로 백업을 실행하지 않는다.

## 5. 복사와 결과 판정

- 원본은 읽기만 하고, 파일 내용·파일명·폴더 구조를 수정하거나 삭제하지 않는다.
- 원본에 임시 파일·로그·설정 파일·검사용 파일을 쓰지 않는다. 원본의 권한이나 속성을 변경해 접근 오류를 해결하지 않는다.
- 선택한 항목 폴더 내부의 일반 파일과 하위 폴더를 재귀적으로 복사한다. 빈 폴더도 보존한다.
- 원본 기본 경로 전체를 재귀 복사하지 않는다. 선택하지 않은 항목과 기본 경로의 다른 폴더는 복사 대상에 포함하지 않는다.
- 백업 파일·복사용 임시 파일·미완료 표식은 이번에 만든 백업 폴더에만 기록한다. 설정과 로그는 원본 밖의 프로그램 사용자 데이터 영역에 기록한다.
- 숨김 파일이라는 이유만으로 제외하지 않는다. 읽을 수 없는 항목은 실패로 표시한다.
- 링크나 정션은 따라가지 않고 제외 항목으로 보고한다. 제외가 있으면 완전한 성공으로 표시하지 않는다.
- 파일명, 확장자, 상대 경로, 파일 내용을 보존한다. 파일의 최종 수정 시각도 가능한 경우 유지하고, 유지하지 못하면 상세 결과에 표시한다.
- 대상 목록은 준비 단계에서 확정한다. 목록 확정 후 추가된 파일은 다음 백업 대상이다.
- 파일별로 임시 이름에 복사하고, 복사 성공과 파일 크기를 확인한 후 원래 이름으로 확정한다.
- 파일 크기 확인은 기본 복사 확인이며, 암호학적 해시 검증을 의미하지 않는다.
- 복사 전후 원본 크기나 수정 시각이 달라진 파일은 한 번 재시도한다. 재시도 후에도 변하면 실패로 처리한다.
- 개별 파일 오류는 기록하고 가능한 나머지 파일을 계속 복사한다. 저장 공간 부족이나 저장 위치 연결 끊김처럼 작업 전체를 진행할 수 없는 오류는 중단한다.
- 성공적으로 복사된 파일, 실패한 파일, 제외 항목, 시각과 실제 경로를 실행별 로그에 기록한다. 로그는 프로그램의 사용자 데이터 영역에 보관해 백업 파일과 이름이 충돌하지 않게 한다.

| 결과 상태 | 판정 기준 |
| --- | --- |
| 완료 | 확정된 대상의 복사와 기본 확인이 끝났고 실패·제외·메타데이터 경고가 없음 |
| 일부 실패 | 복사를 마쳤으나 실패·제외 항목 또는 메타데이터 경고가 있음 |
| 실패 | 사전 검사 실패 또는 작업 전체를 계속할 수 없어 중단 |
| 취소 | 사용자가 중단했으며 아직 처리하지 않은 항목이 있음 |

준비 중 만든 항목별 날짜 폴더에는 완료 전까지 `__미완료` 표식을 붙인다. 해당 항목의 작업이 모두 성공했을 때만 표식을 제거하고 예정된 폴더명으로 확정한다. 일부 실패·실패·취소 또는 비정상 종료 시에는 해당 항목의 표식을 유지해 완성된 백업으로 오인하지 않게 한다. 표식 제거 중 이름이 중복되면 다음 번호를 다시 결정한다.

한 실행에서 항목별 결과를 각각 표시하고 전체 결과를 함께 집계한다. 일부 항목만 성공했으면 전체를 완료로 표시하지 않는다. 취소나 중단 시 이미 완료한 항목의 백업은 완료 상태를 유지하고, 미시작 항목은 미실행으로 표시한다.

취소 시 완성된 복사본은 남겨 두고, 이번 작업이 만든 복사 중 임시 파일만 제거한다. 제거하지 못한 임시 파일은 상세 결과에 남긴다. 이전 백업과 원본 파일은 건드리지 않는다.

여러 파일을 순차적으로 복사하는 방식이므로, 계속 수정되는 프로그램 데이터 전체가 정확히 같은 순간의 상태로 저장되는 것은 보장하지 않는다. 같은 시점의 파일 세트가 필요하면 해당 파일의 기록이 멈춘 상태에서 실행한다.

## 6. 실행 전 검사와 오류 안내

| 검사·상황 | 프로그램 동작 |
| --- | --- |
| 기본 경로 미설정 | 경로 설정 안내 후 시작 차단 |
| 선택된 항목 없음 | 항목 선택 안내 후 시작 차단 |
| 원본 항목 없음 또는 읽기 불가 | 해당 항목 상태 표시 및 선택 제한; 선택 후 상태가 바뀌었으면 실행 전 검사를 실패 처리 |
| 백업 기본 경로 없음 또는 쓰기 불가 | 원인 표시 후 시작 차단 |
| 백업 경로에 선택 항목의 부모 폴더만 없음 | 원본 밖의 백업 위치에 해당 부모 폴더 생성 |
| 백업 쓰기 경로가 원본 항목과 같거나 그 내부임 | 원본 수정 및 자기 복사를 막기 위해 시작 차단 |
| 빈 이름·유효하지 않은 이름 | 해당 입력란에 수정할 내용 표시 |
| 선택한 원본 항목이 비어 있음 | 해당 항목 아래에 빈 날짜 폴더 생성 후 파일 0개로 완료 |
| 시작 전 공간 부족 확인 | 필요한 용량과 가용 용량을 표시하고 시작 차단 |
| 가용 용량을 확인할 수 없음 | 확인 불가 상태를 표시하며 복사 중 쓰기 오류를 처리 |
| 파일 잠김·권한 부족·복사 중 삭제 | 파일 경로와 원인 기록, 일부 실패로 보고 |
| 실행 중 원본 연결 끊김 | 접근 실패 항목 기록, 진행 불가능하면 중단 |

경로 비교 시 정규화된 실제 경로를 사용한다. 백업 쓰기 경로는 선택 여부와 관계없이 원본의 여섯 항목 폴더 내부에 놓일 수 없다. 단, 원본 기본 경로의 별도 `backup` 가지처럼 실제 원본 항목들과 겹치지 않는 위치는 허용한다. 부모 경로를 공유한다는 이유만으로 차단하지 않는다. 링크·정션을 따라 원본으로 쓰기가 향하지 않는지도 검사한다. 기존 백업의 삭제나 자동 정리는 수행하지 않는다.

## 7. 1차 범위와 완료 기준

1차 구현은 기본 경로와 여섯 항목을 자동 표시하고, 사용자가 선택한 하나 이상의 항목을 각 대응 폴더 안으로 수동 백업하는 Windows GUI에 집중한다. 개별 파일 선별, 새로운 항목의 임의 등록, 예약 실행, 실시간 감시, 변경 파일만 복사, ZIP 압축, 자동 보관 기간 관리, 전용 복원 기능은 추가 요구가 있을 때 별도로 명세한다.

개발 완료 시 다음 시나리오를 확인한다.

1. 실행 시 설정된 두 기본 경로와 정확한 여섯 항목명이 표시되고 자동 백업은 시작되지 않는다.
2. `1_LEAD`만 선택하면 `<백업기본경로>\1_LEAD\YYMMDD_이름`에만 백업하고 다른 항목에는 날짜 폴더를 생성하지 않는다.
3. `1_LEAD`와 `3_BODY`를 선택하면 각 대응 폴더 아래에 같은 날짜·입력 글을 사용하는 백업이 각각 만들어진다.
4. 날짜 폴더 바로 안에 원본 파일과 하위 폴더·빈 폴더가 복사되며 항목 폴더가 중복으로 끼어들지 않는다.
5. 원본에 쓰기 권한이 없어도 읽기 권한이 있고 백업 위치에 쓰기 권한이 있으면 실행할 수 있다. 작업 과정에서 원본에 쓰기·삭제·이동·이름 변경을 요청하지 않는다.
6. 동일 날짜·이름으로 재실행하면 해당 항목에서 번호가 붙고 이전 백업은 유지된다.
7. 백업 위치가 원본 항목 내부면 차단하고, 공통 부모 아래의 별도 백업 가지이면 정상 실행한다.
8. 잠긴 파일이나 읽을 수 없는 하위 폴더의 오류를 누락하지 않고 해당 항목 결과와 미완료 표식에 반영한다.
9. 취소·공간 부족·연결 끊김 후에도 원본과 이전 백업은 유지되며, 미완성 결과는 완료로 표시하지 않는다.
10. 다음 실행에서 기본 경로와 이름은 복원되고, 날짜는 새로 계산되며 체크 상태는 모두 해제된다.
