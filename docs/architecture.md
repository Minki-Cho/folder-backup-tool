# 구현 메모

1.2.0의 **백업 후 적용**은 별도 `ApplyEngine`이 처리합니다. 기존 `BackupEngine`의 원본 읽기 전용 동작은 유지합니다. 적용 모드에서 사용자가 고른 한 항목 전체를 먼저 백업하고, 완전한 백업 성공 후에만 드래그한 파일·폴더 내용으로 해당 항목의 파일을 교체하거나 추가합니다. 자세한 경계와 실패 처리 규칙은 [적용 계약](apply-contract.md)을 참고하세요.

GUI는 Windows Forms, 백업 엔진은 UI에 종속되지 않는 동기식 C# 클래스로 구성합니다. 화면은 작업 스레드에서 엔진을 실행하고 진행 상황을 100ms 주기로 받아 표시합니다. 네트워크 원본의 상태 확인과 중복 경로 미리보기도 작업 스레드에서 처리합니다.

## 원본 접근과 경로 보호

파일 본문은 `FileAccess.Read`로만 엽니다. 원본에서 속성, 목록, 파일 크기와 수정 시각을 읽습니다. 원본 권한·속성 변경, 원본 안의 검사 파일 생성, 원본 삭제·이동 호출은 하지 않습니다.

`PathSafety`는 절대 경로를 정규화한 후 [GetFinalPathNameByHandleW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew)로 기존 경로의 실제 위치를 확인합니다. 아직 없는 경로는 가장 가까운 기존 상위 폴더의 실제 위치를 기준으로 계산합니다. 실제 위치를 확인하지 못하면 검사를 통과시키지 않습니다.

백업 기본 위치와 선택한 항목의 부모 위치를 설정된 원본 여섯 항목 전체와 비교합니다. 항목 이름을 바꾼 뒤에도 최초 기본 항목 경로의 보호를 유지합니다. 소스와 별개의 백업 가지는 허용합니다. 백업 기본 폴더의 쓰기 권한은 임시 검사 파일을 만들지 않고 Windows에 디렉터리 쓰기 접근 권한을 요청하여 확인합니다. 이후 실제 생성 실패도 처리합니다.

하위 소스 링크·정션은 탐색 중 제외합니다. 복사 직전과 직후에 소스의 하위 경로를 다시 확인하고, 대상에 쓸 때 새 백업 폴더의 경로를 재확인합니다. 이는 통상적인 경로 오류와 링크 변경을 방어하지만, 악의적인 외부 프로세스가 동시에 디렉터리를 교체하는 상황에 대한 파일 시스템 트랜잭션이나 격리는 아닙니다.

## 복사 단계

1. 요청의 선택 항목·이름·클릭 시각을 복제해 실행 중 입력 변경과 분리합니다.
2. 기본 경로와 선택 항목을 확인하고 사용자 데이터 영역에 실행 로그를 생성합니다.
3. 선택 항목을 순회하여 파일과 빈 폴더 목록을 확정합니다. 접근하지 못한 하위 경로와 링크 제외를 기록합니다.
4. 실제 저장 예정 경로 길이와 필요한 파일 크기 합계를 검사합니다.
5. 항목별로 선택 부모 폴더를 준비하고, Windows `CreateDirectoryW`를 이용해 미완료 폴더를 독점 생성합니다.
6. 파일마다 새 임시 파일을 만들고 읽기·쓰기, 디스크 flush, 크기 비교를 수행합니다. 소스의 전후 크기·수정 시각이 달라지면 한 번 다시 복사합니다.
7. 수정 시각을 보존하고 임시 파일을 원래 이름으로 바꿉니다. 중복이 생기면 기존 파일을 덮어쓰지 않습니다.
8. 오류·제외·경고가 없는 항목만 최종 이름으로 바꿉니다. 최종 이름을 다른 실행이 먼저 만들었으면 새 번호로 다시 확정합니다.

파일 오류는 다음 파일 처리를 계속합니다. 공간 부족, 치명적인 장치·연결 오류와 로그 기록 실패는 실행을 중단합니다. 모든 완료 결과를 보존하면서 현재 항목과 미시작 항목을 구분합니다.

## 로그와 설정

설정 XML은 같은 사용자 데이터 폴더의 임시 파일에 쓴 뒤 교체합니다. XML 외부 리소스 로딩을 허용하지 않습니다. 손상된 설정의 경로를 임의의 기본값으로 대체해 실행하지 않습니다.

1.1.0부터 `MachineProfile.ItemNames`에 호기별 실제 폴더 이름 6개를 저장합니다. 이전 XML에 항목 이름이 없으면 최초 이름을 적용하고 기존 경로와 백업 이름은 유지합니다. 입력값은 단일 폴더 이름인지, 여섯 이름이 대소문자 구분 없이 서로 다른지 검사합니다. 백업 요청은 선택 항목뿐 아니라 전체 설정 이름을 복제하여 전달하고 모든 쓰기 검사에 사용합니다. 전역 기본 배열을 장비 선택에 따라 변경하지 않습니다.

설정 저장 위치도 두 호기의 전체 항목과 비교합니다. 경로 문자열 중첩과 로컬 실제 경로·정션 중첩을 검사하여 원본 내부에 설정 파일을 쓰지 않도록 합니다. 설비가 오프라인일 때도 설정할 수 있도록 이 설정 저장 검사에서는 원격 공유를 열지 않습니다. 실제 백업을 시작할 때는 엔진이 원격 원본의 실제 경로와 로그 위치까지 다시 검사합니다.

실행 로그는 UTF-8 JSONL로 매 기록마다 flush합니다. 성공 파일의 기록 시점 경로는 복사 중의 미완료 위치이며, 완료 이벤트에서 최종 위치와 이름 변경 내역을 남깁니다. 화면에 전달하는 상세 경로는 최종 위치로 갱신합니다.

소스가 계속 갱신되는 동안의 시점 일관성, 원본 프로그램 잠금, VSS, 암호학적 검증, 예약 실행과 자동 백업 정리는 구현 범위에 포함하지 않습니다.
